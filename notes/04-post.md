## 04 Post (`/posts/[slug]`)

### รูป

## สารบัญ (`ContentsRail`)

ขีดสั้นเรียงแนวตั้งข้างขวา ค้างกลางจอ · v4 ซ่อนต่ำกว่า 1280 แต่เจ้าของอยากให้มีทุกขนาด

### รายการ

- `Title` → ชื่อบทความ (ห่างบน 96) · h2/h3 ในบทความ (01, 02, 02.1) · `End` → Previous | Next (04) / Back to Projects (04B)
- Title กับ End ไม่มีเลขนำ (เจ้าของ 30 ก.ย. 69) · End เป็นข้อเสนอของเจ้าของ
- บทความที่มีหัวข้อไม่ถึง 2 ข้อ = ไม่แสดง

### ตำแหน่ง

- อยู่ใน `.railZone` (หัวบทความ + เนื้อหา)
- **ค้างกลางจอตั้งแต่บนสุดของหน้า ไม่มีขอบบน** (เจ้าของ: "สูงเท่าไหร่ก็ได้ ขอแค่กลางจอ")
  - เคยให้เริ่มที่เส้นล่าง Category / Tags แล้วเปลี่ยนใจ
- หยุดเหนือเส้นบนของ Previous | Next เสมอ · ระยะ `--rail-end`: คอม 24px · จอสัมผัส 40px (กันนิ้วโดน)
- **คอม:** จอเตี้ยที่ถ้าอยู่กลางจอจะชนเส้นตอนถึงก้นหน้า → ค้างสูงขึ้นพอดีไม่ชนตั้งแต่แรก (แถบไม่ขยับหนีเมาส์)
- **มือถือ:** ค้างกลางจอเสมอ (เดิมกฎไม่ชนดันขึ้นไปค้างที่ ~108px เพราะ footer มือถือสูง)
  - End หยุดที่ตำแหน่งสุดท้ายที่แถบยังค้างกลางจอ (เผื่อ `slack` ของการกาง) — เจ้าของว่า End ดีแล้ว
  - เลื่อนเองจนสุดหน้า แถบถูก sticky ดันขึ้นตามปกติ
- จัดกึ่งกลางด้วย `top` ที่คำนวณ ไม่ใช้ translateY(-50%) (sticky คิดจากกล่องก่อน transform)
- ≥1280 อยู่ในขอบหน้า (ขีด 20/12, active 32/20 แบบ v4)
- < 1280 ห่างขอบจอ 8px ไม่ทับ scroll indicator ของมือถือ (ขีด 8/5, active 12/8)

### หุบ / กาง

- **หุบ:** ขีดเรียงชิด ห่างกัน `--pitch-shut` 8px (≥1280: 10px) รอบกลางแถบ
- **กาง:** ขยายเป็นระยะ 24px แบบ smooth 0.36s · **ขีดใต้เมาส์/นิ้วอยู่กับที่** ขีดอื่นกางออกจากมัน
  - v4 กาง 4 → 12 จากขอบบน ขีดใต้เมาส์เลยเลื่อนหนี (เจ้าของเจอ)
  - ขยับด้วย transform กล่องแถบจึงไม่เปลี่ยน
  - การกางไม่ล้ำช่วงของแถบ คิดใหม่ทุกครั้งที่เลื่อน (เคยทับเส้น Previous | Next ตอนลากลงสุด)
- **หุบแล้วถูกดันที่ก้นหน้า:** กลุ่มขีดเลื่อนลงใช้ที่ว่างในกรอบก่อน แล้วค่อยขึ้นตาม
  - ขีดสุดท้ายห่างเส้น 53px บนมือถือ (เดิมลอย 94px — เจ้าของทัก)
  - ตามหน้าเลื่อนแบบทันที (`data-follow` ปิด transition)

### หัวข้อที่อ่านอยู่

- = หัวข้อสุดท้ายที่ขอบบนเลย 35% ของจอ · เลื่อนถึงก้นหน้า = หัวข้อสุดท้าย
- ขีดยาวขึ้นเป็นสีดำ + จุด 6px โค้งไปหา (480ms แบบ v4)
- ข้อที่กดไป ไฮไลต์ค้างจนผู้อ่านเลื่อนเกิน 40px (ส่วนสั้นอย่าง 02.1 เดิมถูกแย่งไฮไลต์)
- ไปหัวข้อ = เลื่อนนุ่มให้ห่างบน 96 แล้วเช็กซ้ำหลังหยุด (รูป lazy ดันเนื้อหาลง)

### เมาส์

- hover = ชื่อหัวข้อกางออกทางซ้ายบนพื้นขาว · คลิกได้ทั้งขีดและชื่อ
- **ลาก = ถึงขีดไหน slide ไปหัวข้อนั้น** แบบเดียวกับนิ้ว (เจ้าของ 30 ก.ย. 69 — เดิมเลื่อนต่อเนื่อง)
- เมาส์ขยับเกิน 4px = เริ่มลาก · พื้นที่จับกว้างเลยขีดไปทางซ้าย 28px
- คลิกรัว 7 ข้อถูกทุกข้อ แถบไม่ขยับ (Safari จอสูง 948 และ 748)

### นิ้ว (จอสัมผัส)

- แตะแถบ = กางชื่อ · แตะชื่อ = ไปหัวข้อ (หุบใน 0.6s) · ไม่แตะ 3 วิ = หุบ
- กางอยู่แล้วแตะที่อื่น หรือหน้าเลื่อน = หุบทันที ไม่กระโดดไปไหน และไม่กดโดนลิงก์ข้างใต้
- **ลาก** (เจ้าของขอกลับมา — ช่วงหนึ่งเป็นแตะอย่างเดียว)
  - ขยับเกิน 10px = เริ่มลาก กางชื่อ
  - ถึงขีดไหน slide ไปหัวข้อนั้น (แบบต่อเนื่องเจ้าของว่าไหลช้า)
  - ขีดที่นิ้ววางลงตอนแรกไม่นับ (หุบอยู่ขีดห่าง 8px นิ้วที่ตั้งใจแตะ 01 มักลงบน 02.1)
  - ตำแหน่งขีดจำไว้ตอนเริ่มลาก (`holdTicks`) · ระหว่างลากขีดไม่ขยับ
  - ยกนิ้วแล้วหุบใน 0.6s
- **เลื่อนเลยจนแถบถูกดันขึ้นแล้วแตะ** = กางพร้อมพาหน้ากลับไปที่ End แถบกลับกลางจอ (เจ้าของเสนอ)
  - ลากทันทีตอนถูกดันยังเป็นแบบเดิม
- iOS
  - `preventDefault` ตั้งแต่ touchstart และทุก touchmove — iOS Safari ไม่รองรับ `touch-action: none` และเมื่อเริ่มเลื่อนหน้าแล้วหยุดไม่ได้
  - ใช้ touch events (pointer events บน iOS Safari ไม่เสถียร)
  - ปิดไฮไลต์เทาตอนแตะ (`-webkit-tap-highlight-color`)
  - ซ่อน scroll bar ของระบบบนหน้าบทความ (`html[data-rail]` + `pointer: coarse`) — Safari ซ่อนให้ (เจ้าของยืนยัน)

### กลับสีบนของดำ (เจ้าของขอ, ต่างจาก v4)

## สารบัญบน iPad (2 ต.ค. 69) — แก้แล้ว
- iPad = จอขนาดคอม (CSS ตามความกว้าง) + จอสัมผัส (JS ตาม pointer: coarse) · Safari บน iPad บอกเว็บว่าเป็น "Macintosh" → แยกจากชื่อเครื่องไม่ได้ ต้องดูจากชนิดการแตะ
- หาสาเหตุจากบันทึกจริงบน iPad (ตัวบันทึกชั่วคราว + `fetch` ส่งกลับ Mac) ไม่ใช่จากวิดีโอ
- สาเหตุ 1 — จุดวาร์ป: วิ่งโค้งรอบใหม่เริ่มจาก "ปลายทางรอบก่อน" → แก้: เริ่มจากตำแหน่งที่วาดอยู่จริง (tablet เท่านั้น)
- สาเหตุ 2 — หัวข้อสลับไปมา: ระหว่างหน้าเลื่อน Safari รายงานตำแหน่งนิ้วผิดได้ถึง ~300 px ตามทิศที่เลื่อน = [WebKit bug 181954](https://bugs.webkit.org/show_bug.cgi?id=181954) (เปิดตั้งแต่ 2018)
  - ลองแล้วไม่ได้: `screenY` (นับรวมการเลื่อนหน้า) · `pageY − scrollY` (เท่ากับ clientY ทุกค่า) · กระโดดทันที (หน้ากะพริบ — เจ้าของไม่เอา)
  - ใช้: ลากด้วยนิ้ว = จุดกับชื่อตามนิ้ว · นิ้วค้างบนหัวข้อ 120 ms (`DWELL`) หน้าเลื่อนนุ่มไป · ระหว่างหน้าเลื่อน + ค่าแรกหลังหยุด ไม่อ่านนิ้ว · ปล่อยนิ้ว = ไปหัวข้อสุดท้ายที่เลือก
  - เลขหัวข้อโดดเล็กน้อยตอนหน้าเลื่อน = มาจากการหน่วง ยอมรับได้ (เจ้าของ)
  - **เฉพาะ tablet** = จอสัมผัส + ด้านสั้นของจอ ≥ 600 (iPad ≥ 744 · iPhone ≤ 440) ไม่ขึ้นกับการหมุนจอ · คอมกับ iPhone เหมือนเดิมทุกอย่าง (เจ้าของ, 2 ต.ค. 69 — ลองบน iPhone แล้วไม่ชอบ)
  - iPhone ก็มีบั๊ก WebKit ตัวเดียวกัน แต่สารบัญเตี้ย นิ้วข้ามหัวข้อน้อย เจ้าของรับได้
- อ่านนิ้วตัวที่เริ่มแตะสารบัญ (`identifier`) ไม่ใช่ `touches[0]`
- scroll bar บน iPad ไม่หาย: iPad เครื่องนี้ iPadOS 17.7 (อัปไม่ได้แล้ว) · `scrollbar-width` ต้อง Safari 18.2+ → ปล่อยไว้

## สารบัญ: ชื่อหัวข้อยาว (3 ต.ค. 69)
- ป้ายชื่อในสารบัญยาวสุด 240px แล้วต่อด้วย … (`.tocLabel` max-width) — v4 ไม่มีกำหนด (`.tl` ไม่มี max-width) แต่หัวข้อยาวกินครึ่งหน้า · มีผลทั้งหน้าเว็บ, Preview และ WRITE
- **Carousel วนรอบทั้งนิ้วและปุ่ม** (เจ้าของ, 4 ต.ค. 69 — เดิมนิ้วหยุดที่ปลาย ปุ่มวนแบบเลื่อนย้อนทั้งแถว): track มีสำเนารูปสุดท้ายไว้หน้ารูปแรก และรูปแรกไว้ท้ายสุด · ถึงสำเนาแล้วสลับเป็นรูปจริงตรงนั้นโดยไม่เลื่อน · ทดสอบ Chrome: 01 → Previous → 04, 04 → Next → 01 · รูปเดียวยังลากหนืดแล้วเด้งกลับ

- TableScroll เคยใส่ `::-webkit-scrollbar { display: none }` (4 ต.ค. 69) → scrollbar ของหน้าหายบน iPhone อีก (ดูหัวข้อ scrollbar บนมือถือใน shared.md) → เหลือแค่ scrollbar-width

## 5 ต.ค. 69 (ค่ำ)
- ปกบทความ `next/image` quality 90 (`images.qualities: [75, 90]`) — ปกที่เป็นแผนผัง/ตัวหนังสือเบลอที่ 75 บนจอใหญ่ · ที่อื่นยัง 75
- Carousel: พื้นที่ปัดนิ้วกว้างถึงขอบจอ (`.swipe` + `--edge-l/--edge-r` วัดจาก figure) ไม่ใช่แค่ในรูป — 4:5 บนมือถือรูปกว้างแค่ ~170px เดิมต้องปัดในรูปเท่านั้น · ครึ่งซ้าย/ขวาของเมาส์ (desktop) ถึงขอบจอทั้ง 2:1 และ 4:5 อยู่แล้ว (เช็ก 1440: 0–712 / 712–1425)

- **กดรูปเพื่อดูเต็มจอ** (`Lightbox.tsx`, เจ้าของเลือก B): รูปทุกแบบในบทความ (`data-zoom`) กดแล้วเปิดทับหน้า พื้นดำ 96% + คำบรรยาย · ปิด: × / Esc / กดข้างรูป / มือถือดึงลงเกิน 90px · มือถือซูมสองนิ้ว (pinch ของหน้าเอง) · เมาส์: กดรูป = ขยาย (พิกเซลจริงของไฟล์ หรืออย่างน้อย 2 เท่า) แล้วรูปเลื่อนตามเมาส์ · เปิดอยู่ = หน้าหลังเลื่อนไม่ได้
  - **ปรับ 6 ต.ค. 69 (เจ้าของ)**: เมาส์เปิดได้จากปุ่ม ⤢ มุมขวาบนเท่านั้น (ทุกรูป ไม่ใช่แค่ carousel) · ตัวรูปเป็นเมาส์ปกติ ไม่มีแว่นขยายเลย (ใน Lightbox ด้วย) · ปุ่ม: ไม่มีพื้น มีแค่เส้นขอบมุมมน 10px #e8e8e7 ไม่มีเงา (ลอง difference = หม่นบนรูปถ่าย, เลือกสีจากมุมรูป = เจ้าของว่าไม่ work) · ขึ้นตอน hover รูป · เมาส์บนปุ่ม = นิ้ว + ลูกศรสองข้างเด้งออกจากกลางแล้วกลับที่เดิม 0.5s (ครั้งเดียวต่อการเข้า) · มือถือแตะรูปเหมือนเดิม
  - carousel (6 ต.ค. 69): ⤢ ขึ้นเฉพาะตอนเมาส์อยู่บนตัวรูป (`data-over` จาก mousemove เทียบกรอบรูป — ครึ่งซ้าย/ขวายื่นถึงขอบจอ hover ครึ่งนอกรูปไม่นับ) · เมาส์: ซ่อนแถว Previous / Next + เส้น (`visibility: hidden` กันหน้ากระโดด) เพราะครึ่งรูปบอกอยู่แล้ว · สารบัญเปิด (ครึ่งรูปปิด) = แถวกลับมา · มือถือยังมีแถว
  - carousel บน desktop: ครึ่งซ้าย/ขวาเป็นปุ่มเลื่อนอยู่แล้ว → ปุ่ม ⤢ มุมขวาบนของรูป ขึ้นตอน hover · มือถือแตะรูปได้เลย (ปัดไม่นับเป็นแตะ) · รูปใน carousel ใช้คำบรรยายของตัวเอง (`data-caption`) ไม่ใช่ของ figure ที่มี "01 / 03"
  - ฟังเฉพาะใน `.body` ของบทความ (หน้าโพสต์ + Preview) · กล่อง WRITE ใน Editor ไม่มี
